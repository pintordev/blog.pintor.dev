## 문제

> 링크: [프로그래머스 64063](https://school.programmers.co.kr/learn/courses/30/lessons/64063)

1번부터 k번까지의 방이 있는 호텔에서, 고객이 원하는 방이 비어 있으면 그 방을, 이미 찼다면 그보다 번호가 크면서 비어 있는 방 중 가장 작은 번호를 배정할 때 각 고객이 받는 방 번호를 순서대로 구하는 문제.

## 접근

### 선형 탐색은 시간 초과

배정된 방을 Set에 저장하고, 원하는 방이 찼다면 번호를 1씩 늘려가며 빈 방을 찾는 방법이 가장 단순하다. 하지만 같은 방을 계속 요청하면 매번 탐색 길이가 늘어나 최악의 경우 O(N²)이 된다. 요청이 최대 200,000개이므로 통과할 수 없다.

### HashMap 기반 Union-Find

`parent[x]`를 "x 이상에서 가장 가까운 빈 방 후보"를 가리키는 포인터로 정의한다. 방이 배정되면 그 방은 바로 다음 방(`x + 1`)을 가리키게 하고, 빈 방을 찾을 때는 이 포인터를 따라가면 찬 방을 한 번에 건너뛸 수 있다.

k가 최대 10^12이므로 배열로는 관리할 수 없다. 배정된 방만 `HashMap<Long, Long>`에 기록하고, 맵에 없는 방은 비어 있는 것으로 본다. 공간은 O(N)이다.

- 원하는 방 `x`에 대해 `putIfAbsent(x, x + 1)`을 호출한다. 반환값이 `null`이면 비어 있던 방이므로 점유 표시와 배정이 한 번에 끝난다.
- 이미 찬 방이면 포인터를 따라가며 마찬가지로 `putIfAbsent`로 빈 방을 찾는다. 처음 만나는 빈 방이 점유되면서 배정할 방이 된다.
- 탐색이 끝나면 경로상의 모든 방이 `room + 1`을 가리키도록 갱신한다. 경로상의 방은 모두 찬 방이고 `room`도 방금 점유되었으므로, 다음 빈 방 후보는 `room + 1`부터다.

체인이 최대 200,000까지 길어질 수 있어서 재귀 대신 반복문으로 구현해 스택 오버플로를 피한다.

경로 압축 덕분에 연산당 amortized O(log N)이고, 전체 시간복잡도는 O(N log N)이다.

## 풀이

```java
import java.util.HashMap;
import java.util.Map;

Map<Long, Long> parent;

public long[] solution(long k, long[] room_number) {
    parent = new HashMap<>();
    long[] res = new long[room_number.length];
    for (int i = 0; i < room_number.length; i++) {
        res[i] = reserve(room_number[i]);
    }
    return res;
}

public long reserve(long x) {
    Long next = parent.putIfAbsent(x, x + 1);
    if (next == null) return x;
    long room = next;
    while (true) {
        Long n = parent.putIfAbsent(room, room + 1);
        if (n == null) break;
        room = n;
    }
    while (x != room) {
        long n = parent.get(x);
        parent.put(x, room + 1);
        x = n;
    }
    return room;
}
```

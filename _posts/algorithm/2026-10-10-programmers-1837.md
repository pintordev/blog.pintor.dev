## 문제

> 링크: [프로그래머스 1837](https://school.programmers.co.kr/learn/courses/30/lessons/1837)

오류가 섞인 GPS 기록이 주어질 때, 출발·도착 거점은 고정한 채 유효한 이동 경로가 되도록 바꿔야 하는 기록의 최소 개수를 구하는 문제. 불가능하면 -1을 반환한다.

## 접근

### 시간축 DP

택시는 한 번에 인접한 거점으로 이동하거나 같은 거점에 머무를 수 있다. 그래서 t번째 기록 시점에 어느 거점에 있는지만 정해지면, 그 이후의 최소 수정 횟수는 이전 기록과 무관하게 결정된다.

- 상태: `dp[t][v]`는 t번째 시점에 거점 v에 있을 때까지의 최소 수정 횟수
- 초기값: `dp[0][gps_log[0]] = 0`, 나머지는 `Integer.MAX_VALUE`. 출발 거점은 바꿀 수 없기 때문이다.
- 전이: 이전 시점의 거점 u에서 v로 이동할 수 있으면(`v == u`이거나 도로가 있으면) `dp[t][v] = min(dp[t][v], dp[t - 1][u] + (gps_log[t] == v ? 0 : 1))`
- 답: `dp[k - 1][gps_log[k - 1]]`. 도착 거점도 바꿀 수 없으므로 이 칸만 본다. `MAX`이면 -1이다.

머무름은 각 거점의 인접 리스트에 자기 자신을 넣어 처리한다. 도로가 양방향이므로 간선은 양쪽으로 등록한다. 이전 시점에 도달할 수 없는 거점(`MAX`)은 인접 리스트를 순회하기 전에 건너뛴다.

시간복잡도는 O(k·(n+m)), 최악 약 2백만 연산이라 제약을 충분히 만족한다.

## 풀이

```java
import java.util.*;

public int solution(int n, int m, int[][] edge_list, int k, int[] gps_log) {
    List<Integer>[] graph = new List[n + 1];
    for (int i = 1; i <= n; i++) {
        graph[i] = new ArrayList<>();
        graph[i].add(i);
    }
    for (int[] edge : edge_list) {
        graph[edge[0]].add(edge[1]);
        graph[edge[1]].add(edge[0]);
    }
    int[][] dp = new int[k][n + 1];
    for (int[] row : dp) {
        Arrays.fill(row, Integer.MAX_VALUE);
    }
    dp[0][gps_log[0]] = 0;
    for (int t = 1; t < k; t++) {
        for (int u = 1; u <= n; u++) {
            if (dp[t - 1][u] == Integer.MAX_VALUE) continue;
            for (int v : graph[u]) {
                dp[t][v] = Math.min(dp[t][v], dp[t - 1][u] + (gps_log[t] == v ? 0 : 1));
            }
        }
    }
    int res = dp[k - 1][gps_log[k - 1]];
    return res == Integer.MAX_VALUE ? -1 : res;
}
```

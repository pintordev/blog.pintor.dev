## 문제

> 링크: [프로그래머스 17686](https://school.programmers.co.kr/learn/courses/30/lessons/17686)

파일명을 HEAD / NUMBER / TAIL로 분리해 HEAD 사전순 → NUMBER 숫자순 → 입력 순서 유지 기준으로 정렬한다.

## 접근

### 정규식으로 파싱 후 정렬

파일명에서 HEAD(첫 영문자 덩어리)와 NUMBER(첫 숫자 덩어리, 최대 5자리)를 정규식으로 추출한다. 추출한 값을 필드로 갖는 객체를 만들고, `Comparable`을 구현해 `Arrays.sort`로 정렬한다.

HEAD·NUMBER가 같을 때 입력 순서를 유지해야 하는데, `Arrays.sort`는 TimSort 기반의 안정 정렬이므로 별도 처리 없이 보장된다.

## 풀이

```java
import java.util.Arrays;
import java.util.regex.Matcher;
import java.util.regex.Pattern;

public String[] solution(String[] files) {
    File[] parsed = new File[files.length];
    for (int i = 0; i < files.length; i++) {
        parsed[i] = new File(files[i]);
    }
    Arrays.sort(parsed);
    String[] res = new String[files.length];
    for (int i = 0; i < files.length; i++) res[i] = parsed[i].name;
    return res;
}

class File implements Comparable<File> {
    static Pattern p = Pattern.compile("^([a-zA-Z\\-. ]+?)(\\d{1,5})");
    String name;
    String head;
    int number;

    File(String name) {
        this.name = name;
        Matcher m = p.matcher(name);
        m.find();
        this.head = m.group(1).toLowerCase();
        this.number = Integer.parseInt(m.group(2));
    }

    @Override
    public int compareTo(File o) {
        if (!this.head.equals(o.head)) return this.head.compareTo(o.head);
        return this.number - o.number;
    }
}
```

## 회고

처음에는 `PriorityQueue`로 구현했다. 그런데 `PriorityQueue`는 불안정 정렬이라, HEAD·NUMBER가 같은 파일이 있을 때 입력 순서가 보장되지 않는다. 이를 해결하려면 객체에 원본 인덱스 `idx`를 저장하고 `compareTo`의 마지막 조건으로 넣어야 한다.

`Arrays.sort`로 바꾸면 이 문제가 사라진다. Java의 `Arrays.sort`는 TimSort 기반의 안정 정렬이라, `compareTo`가 0을 반환하는 두 원소의 상대 순서를 원본 배열 기준으로 자동 보장한다. 덕분에 `idx` 필드 없이 HEAD·NUMBER 비교만으로 충분하다.

## 문제

> 링크: [프로그래머스 138476](https://school.programmers.co.kr/learn/courses/30/lessons/138476)

k개의 귤을 고를 때 크기 종류의 수를 최소화하는 문제.

## 접근

### 빈도수 정렬 + 그리디

같은 크기끼리 묶어 많이 등장하는 크기부터 고르면 종류 수가 최소가 된다.

1. 정렬 후 연속 구간 길이를 세어 빈도수 집계 → `bucket[r]++` (`bucket[i]` = 빈도가 i인 크기의 수)
2. 빈도 큰 것(`i = n → 1`)부터 그리디하게 선택
   - `take = min(bucket[i], ceil(k / i))` : 해당 빈도에서 몇 종류 뽑을지 (k를 초과하지 않도록 올림 나눗셈으로 상한)
   - `k -= take * i`, `cnt += take`
3. k가 0 이하가 되면 종료

HashMap 없이 정렬 + 버킷 배열만으로 구현할 수 있다.

## 풀이

```java
import java.util.Arrays;

public int solution(int k, int[] tangerine) {
    Arrays.sort(tangerine);
    int n = tangerine.length;
    int[] bucket = new int[n + 1];
    int r = 1;
    for (int i = 1; i < n; i++) {
        if (tangerine[i] == tangerine[i - 1]) r++;
        else {
            bucket[r]++;
            r = 1;
        }
    }
    bucket[r]++;
    int cnt = 0;
    for (int i = n; i > 0 && k > 0; i--) {
        int take = Math.min(bucket[i], (k + i - 1) / i);
        k -= take * i;
        cnt += take;
    }
    return cnt;
}
```

## 회고

HashMap으로 빈도 집계 후 값들만 정렬하는 방식 대신, 배열 자체를 정렬하고 연속 구간 길이를 버킷에 담는 방식을 택했다. 추가 자료구조 없이 O(n) 배열 하나로 해결해서 공간 효율이 좋다.

같은 빈도의 크기가 여러 종류일 때 그 중 일부만 뽑아야 하는 경우, `take = ceil(k / i)` 로 상한을 두어 k를 초과하지 않게 처리한 부분이 핵심이었다.

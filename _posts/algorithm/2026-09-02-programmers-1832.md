## 문제

> 링크: [프로그래머스 1832](https://school.programmers.co.kr/learn/courses/30/lessons/1832)

오른쪽·아래로만 이동하는 격자에서, 일부 칸(`2`)에서는 진행 방향을 바꿀 수 없다는 제약을 두고 `(0, 0)` → `(m-1, n-1)` 경로 수를 `20170805`로 나눈 나머지를 구하는 문제.

## 접근

### 진입 방향을 상태에 넣는 격자 DP

이동이 오른쪽·아래뿐이라 사이클이 없어 좌상단부터 채우는 격자 DP가 성립한다. 문제는 `city_map[i][j] == 2`인 칸에서 **진입한 방향으로만 나갈 수 있다**는 것이다. 그래서 "이 칸에 어느 방향으로 들어왔는가"를 상태에 포함한다.

- `dp[i][j][0]` = `(i, j)`에 **위에서** 내려오며 진입한 경로 수
- `dp[i][j][1]` = `(i, j)`에 **왼쪽에서** 오며 진입한 경로 수

전이는 이전 칸의 값에 따라 갈린다. `dp[i][j][0]`을 채울 때 이전 칸은 `(i-1, j)`이고,

- 이전 칸이 `2`면 그 칸은 진입 방향 유지만 되므로, 아래로 나가려면 위에서 들어왔어야 한다 → `dp[i-1][j][0]`만
- 이전 칸이 `0`이면 방향 전환이 자유롭다 → `dp[i-1][j][0] + dp[i-1][j][1]`
- 이전 칸이 `1`이면 그 칸의 dp가 전부 0이라 자동으로 0이 더해진다

`dp[i][j][1]`도 왼쪽 칸 `(i, j-1)`에 대해 대칭으로 처리한다. 이 "이전 칸이 `2`면 같은 방향분만, 아니면 합" 규칙을 `ways(이전칸값, 같은방향dp, 다른방향dp)` 헬퍼로 뽑으면 본문이 두 줄로 줄어든다.

시작칸은 값이 `0`이라 "두 방향 합"을 그대로 쓰면 첫 이동이 두 번 세어진다. `dp[0][0][0] = 1`, `dp[0][0][1] = 0`으로 두면 `(0, 0)`에서 아래로도 오른쪽으로도 각각 1가지가 되어 맞아떨어진다. `(0, 0)`은 루프에서 `i > 0`·`j > 0`이 모두 거짓이라 덮어써지지 않는다.

시간·공간 모두 `O(mn)`이고 `m, n ≤ 500`이라 넉넉히 통과한다.

## 풀이

```java
int MOD = 20170805;

public int solution(int m, int n, int[][] cityMap) {
    int[][][] dp = new int[m][n][2];
    dp[0][0][0] = 1;
    for (int i = 0; i < m; i++) {
        for (int j = 0; j < n; j++) {
            if (cityMap[i][j] == 1) continue;
            if (i > 0) dp[i][j][0] = ways(cityMap[i - 1][j], dp[i - 1][j][0], dp[i - 1][j][1]) % MOD;
            if (j > 0) dp[i][j][1] = ways(cityMap[i][j - 1], dp[i][j - 1][1], dp[i][j - 1][0]) % MOD;
        }
    }
    return (dp[m - 1][n - 1][0] + dp[m - 1][n - 1][1]) % MOD;
}

public int ways(int cell, int same, int other) {
    return cell == 2 ? same : same + other;
}
```

## 문제

> 링크: [프로그래머스 152995](https://school.programmers.co.kr/learn/courses/30/lessons/152995)

완호의 두 점수(근무 태도, 동료 평가)가 모두 어떤 사원보다 낮으면 완호는 인센티브 대상에서 제외되고, 그렇지 않은 사원들은 두 점수 합계로 석차를 매길 때 완호의 석차를 구하는 문제다.

## 접근

### 정렬 후 한 번의 스윕으로 지배 판별 + 석차 계산

모든 사원 쌍을 비교해서 지배 여부를 판별하면 O(n²)이라 n = 100,000 기준으로 시간 초과다. 정렬로 O(n log n)에 해결한다.

근무 태도(a) 기준 내림차순, 동점이면 동료 평가(b) 기준 오름차순으로 정렬한다. 지금까지 살아남은(지배당하지 않은) 사원들의 b 최댓값을 `prev`로 유지하면서, 현재 사원의 b가 `prev`보다 작으면 이미 a도 크고 b도 큰 사원이 나왔다는 뜻이므로 인센티브 대상에서 제외한다. 같은 a끼리는 서로를 지배할 수 없다는 성질과, 동점자를 b 오름차순으로 정렬해두는 트릭 덕분에 `prev`가 단조 증가하며 같은 그룹 내부에서 잘못 제외되는 일이 없다.

완호(`scores[0]`)는 정렬 전에 참조로 미리 잡아둔다. Java의 2차원 배열은 `int[]` 참조들의 배열이라, `Arrays.sort`로 순서를 바꿔도 내부 배열 객체 자체는 그대로 유지되므로 정렬 후에도 `me`가 정확히 완호를 가리킨다.

석차는 별도로 정렬하지 않고, 지배당하지 않은 사원 중 완호보다 합계가 큰 사원 수를 센 뒤 1을 더하는 방식으로 바로 계산한다. 동점자는 자연스럽게 같은 석차를 공유하게 된다.

시간복잡도는 O(n log n), 추가 공간은 정렬 내부 버퍼를 제외하면 O(1)이다.

## 풀이

```java
import java.util.Arrays;

public int solution(int[][] scores) {
    int[] me = scores[0];
    Arrays.sort(scores, (a, b) -> a[0] != b[0] ? b[0] - a[0] : a[1] - b[1]);

    int res = 1;
    int prev = scores[0][1];
    for (int[] score : scores) {
        if (prev > score[1]) {
            if (score == me) return -1;
            continue;
        }
        prev = score[1];
        if (score[0] + score[1] > me[0] + me[1]) res++;
    }
    return res;
}
```

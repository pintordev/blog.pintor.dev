## 문제

> 링크: [프로그래머스 468378](https://school.programmers.co.kr/learn/courses/30/lessons/468378)

열마다 굴착 비용이 다른 격자에서, 보물이 왼쪽·오른쪽 중 어느 쪽에 있는지만 알려주는 `excavate`를 호출해 총비용 `money` 이내로 보물이 있는 열을 찾는 문제.

## 접근

### 구간 DP로 최악 비용이 최소인 질의 순서 구하기

`excavate(k)`의 결과는 세 가지다. 0이면 찾은 것이고, -1이면 `[l, k-1]`, 1이면 `[k+1, r]`로 후보가 좁혀진다. 어느 쪽으로 좁혀질지는 보물 위치에 달려 있으므로, 보물이 가장 불리한 곳에 있다고 가정하고 최악의 비용을 최소화하는 열을 고른다.

- `dp[l][r]`: 보물이 `[l, r]` 안에 있을 때 찾는 데 드는 최악 비용의 최솟값
- `dp[l][r] = min(depth[k] + max(dp[l][k-1], dp[k+1][r]))` (k는 `l`~`r`)
- 빈 구간은 0이고, 후보가 하나여도 0을 받으려면 한 번 파야 하므로 `dp[l][l] = depth[l]`이다.

구간 길이를 1부터 늘려가며 채우고, 각 구간에서 최솟값을 만든 k를 `pick[l][r]`에 저장한다. 이후 `pick[1][w]`부터 실제로 `excavate`를 호출하며 구간을 좁혀 나가면 총비용은 항상 `dp[1][w]` 이하이고, 문제 조건상 이 값은 `money` 이하다.

단순 이분 탐색은 비용이 큰 열을 밟을 수 있어 `money`를 초과할 수 있다. 예를 들어 `[2, 100, 1, 100, 3, 100, 1]`에서 보물이 5열이면 4열(100), 6열(100), 5열(3) 순으로 파게 되어 203이 든다.

- 시간복잡도: O(w³)
- 공간복잡도: O(w²)

## 풀이

```java
import java.util.function.Function;

public int solution(int[] depth, int money, Function<Integer, Integer> excavate) {
    int n = depth.length;
    int[][] dp = new int[n + 2][n + 2];
    int[][] pick = new int[n + 2][n + 2];
    for (int len = 1; len <= n; len++) {
        for (int l = 1; l + len - 1 <= n; l++) {
            int r = l + len - 1;
            dp[l][r] = Integer.MAX_VALUE;
            for (int k = l; k <= r; k++) {
                int cost = depth[k - 1] + Math.max(dp[l][k - 1], dp[k + 1][r]);
                if (cost >= dp[l][r]) continue;
                dp[l][r] = cost;
                pick[l][r] = k;
            }
        }
    }
    int l = 1;
    int r = n;
    while (true) {
        int k = pick[l][r];
        int dir = excavate.apply(k);
        if (dir == 0) return k;
        if (dir < 0) r = k - 1;
        else l = k + 1;
    }
}
```

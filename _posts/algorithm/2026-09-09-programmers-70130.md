## 문제

> 링크: [프로그래머스 70130](https://school.programmers.co.kr/learn/courses/30/lessons/70130)

배열 `a`의 부분 수열 중, 인접한 쌍들이 공통 원소(중심값) 하나를 갖고 각 쌍의 두 값이 서로 다른 "스타 수열"의 최대 길이를 구한다.

## 접근

### 중심값 고정 + 그리디

스타 수열의 정의를 뜯어보면 결국 **모든 쌍이 공유하는 값(중심값) 하나**가 존재해야 한다. 그러니 중심값 `v`를 하나로 고정해두고 "그 `v`를 중심으로 만들 수 있는 쌍이 최대 몇 개인가"를 구한 뒤, 모든 `v`에 대해 최댓값을 취하면 된다.

중심값 `v`가 정해지면 각 쌍은 `{v, w}` (단 `w != v`) 꼴이다. 즉 인접한 두 원소 `a[i]`, `a[i+1]`이 쌍이 될 수 있는 조건은 **둘 중 정확히 하나만 `v`와 같은 것**이다. 둘 다 `v`거나 둘 다 `v`가 아니면 쌍이 안 된다.

이 상태에서 왼쪽부터 훑으며 가능한 쌍을 바로바로 확정하는 그리디가 최적이다. 앞쪽 원소를 최대한 빨리 소비해도 뒤쪽 선택지가 손해 보지 않기 때문이다. `a[i]`, `a[i+1]`이 쌍이 되면 둘 다 소비하고 두 칸 전진, 아니면 한 칸 전진한다.

### 빈도로 가지치기

중심값은 각 쌍에서 딱 한 번씩 등장하므로, 쌍이 `k`개면 `v`가 최소 `k`번 나온다. 따라서 **중심값 `v`로 만들 수 있는 스타 수열 길이는 아무리 커도 `2 * freq(v)`** 다.

그냥 모든 `v`에 대해 배열 전체를 훑으면 `O(n^2)` 이라 `n = 50만` 에서 터진다. 그래서 미리 각 값의 등장 횟수 `freq[]`를 세두고, 현재까지의 최대 답 `best`에 대해 `2 * freq(v) <= best` 인 `v`는 아예 스캔을 건너뛴다. `best`가 빠르게 커지면서 실제로 전체 스캔이 도는 중심값은 몇 개로 확 줄어들어 제한 시간 안에 통과한다.

## 풀이

```java
public int solution(int[] a) {
    int n = a.length;
    int[] freq = new int[n];
    for (int x : a) {
        freq[x]++;
    }
    int best = 0;
    for (int v = 0; v < n; v++) {
        if (freq[v] << 1 <= best) continue;
        int pairs = 0;
        for (int i = 0; i + 1 < n; i++) {
            if ((a[i] == v) == (a[i + 1] == v)) continue;
            pairs++;
            i++;
        }
        best = Math.max(best, pairs << 1);
    }
    return best;
}
```

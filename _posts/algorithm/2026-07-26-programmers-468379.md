## 문제

> 링크: [프로그래머스 468379](https://school.programmers.co.kr/learn/courses/30/lessons/468379)

m×n 격자에서 가로 w, 세로 h 크기의 직사각형 구역을 배치할 때, drops 순서대로 비가 내리는 상황에서 그 구역이 가장 늦게(또는 아예) 비를 맞도록 하는 위치를 찾는 문제다.

## 접근

### hitTime으로 문제 재정의

drops를 그대로 시뮬레이션하면 후보 위치마다 drops를 다시 훑어야 해서 비효율적이다. 대신 각 칸이 처음 비를 맞는 시각을 `hitTime[i][j]`에 미리 기록해두면, 문제는 "h×w 부분사각형 중 hitTime 최솟값이 최대인 곳 찾기"로 바뀐다. 사각형 안의 hitTime 최솟값이 곧 그 사각형이 처음 비를 맞는 시각이기 때문이다.

한 번도 비를 맞지 않는 칸은 `drops.length`로 채운다. 이 값은 실제 시각(0 ~ drops.length-1)보다 항상 크기 때문에, "비를 맞지 않는 위치 우선"이라는 조건이 별도 분기 없이 "최솟값이 크다"는 기준에 자연스럽게 포함된다.

### 2단계 슬라이딩 윈도우 최솟값

h×w 사각형 전체의 최솟값은 행 방향과 열 방향으로 나눠서 구한다.

1. 각 행에서 너비 w짜리 구간의 최솟값을 단조 큐(monotonic deque)로 구해 `rowMin`에 저장한다.
2. `rowMin`의 각 열에서 다시 높이 h짜리 구간의 최솟값을 단조 큐로 구하면, 그 결과가 곧 h×w 사각형 전체의 최솟값이 된다.

단조 큐는 배열을 훑으면서 큐 뒤쪽에 현재 값보다 크거나 같은 원소가 있으면 버리고(더 작은 값이 들어왔으니 이길 수 없다), 큐 앞쪽이 윈도우를 벗어나면 버리는 방식으로 원소당 상각 O(1)에 구간 최솟값을 구하는 기법이다.

### 동점 처리 순서

h×w 최솟값들을 모은 `windowMin`을 행 우선(위에서 아래, 왼쪽에서 오른쪽) 순서로 스캔하면서 엄격히 더 큰 값일 때만 갱신하면, 최댓값이 여러 곳에서 동점일 때 가장 위쪽 행·가장 왼쪽 열이 자동으로 선택된다.

## 풀이

```java
import java.util.Arrays;

public int[] solution(int m, int n, int h, int w, int[][] drops) {
    int INF = drops.length;
    int[][] hitTime = new int[m][n];
    for (int[] row : hitTime) Arrays.fill(row, INF);
    for (int t = 0; t < drops.length; t++) {
        hitTime[drops[t][0]][drops[t][1]] = t;
    }

    int[][] rowMin = new int[m][n - w + 1];
    int[] colDeque = new int[n];
    for (int r = 0; r < m; r++) {
        int head = 0, tail = 0;
        for (int c = 0; c < n; c++) {
            while (tail > head && hitTime[r][colDeque[tail - 1]] >= hitTime[r][c]) tail--;
            colDeque[tail++] = c;
            if (colDeque[head] <= c - w) head++;
            if (c >= w - 1) rowMin[r][c - w + 1] = hitTime[r][colDeque[head]];
        }
    }

    int windowRows = m - h + 1;
    int windowCols = n - w + 1;
    int[][] windowMin = new int[windowRows][windowCols];
    int[] rowDeque = new int[m];
    for (int c = 0; c < windowCols; c++) {
        int head = 0, tail = 0;
        for (int r = 0; r < m; r++) {
            while (tail > head && rowMin[rowDeque[tail - 1]][c] >= rowMin[r][c]) tail--;
            rowDeque[tail++] = r;
            if (rowDeque[head] <= r - h) head++;
            if (r >= h - 1) windowMin[r - h + 1][c] = rowMin[rowDeque[head]][c];
        }
    }

    int max = -1, bestR = 0, bestC = 0;
    for (int r = 0; r < windowRows; r++) {
        for (int c = 0; c < windowCols; c++) {
            if (windowMin[r][c] <= max) continue;
            max = windowMin[r][c];
            bestR = r;
            bestC = c;
        }
    }
    return new int[]{bestR, bestC};
}
```

## 회고

처음에는 열 방향 최솟값을 구하는 루프를 바깥에 두고, 그 안에서 행마다 최댓값을 갱신하는 식으로 짰다. 그런데 이렇게 하면 최댓값이 동점일 때 열이 작은 쪽이 먼저 스캔되어버려서, "가장 위쪽 행 우선"이라는 조건을 만족하지 못하는 경우가 생겼다. `windowMin` 전체를 먼저 채운 뒤 별도로 행 우선 순서로 스캔하는 단계를 분리하고 나서야 동점 처리가 제대로 맞았다. 슬라이딩 윈도우 계산 순서와 동점 처리 스캔 순서는 서로 독립적으로 설계해야 한다는 걸 다시 확인한 문제였다.

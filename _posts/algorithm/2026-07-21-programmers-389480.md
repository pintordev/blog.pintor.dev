## 문제

> 링크: [프로그래머스 389480](https://school.programmers.co.kr/learn/courses/30/lessons/389480)

두 도둑 A, B가 모든 물건을 나눠 훔친다. 물건마다 `[a, b]` 형태로 주어지는데, A가 훔치면 흔적 a가 A에게, B가 훔치면 흔적 b가 B에게 쌓인다. A는 흔적 합이 n 이상이면 잡히고, B는 흔적 합이 m 이상이면 잡힌다. 둘 다 잡히지 않도록 모든 물건을 배정했을 때 A 흔적 합의 최솟값을 구한다. 불가능하면 -1을 반환한다.

## 접근

### B의 흔적 합을 상태로 삼는 DP

물건 수가 최대 40개라 완전탐색(2^40)은 불가능하지만, m이 최대 120으로 작다는 점에 주목한다. `dp[j]`를 "B의 흔적 합이 j일 때 A 흔적 합의 최솟값"으로 정의하면, 물건 하나를 처리할 때마다 두 가지 선택지가 있다.

- A에게 배정: `dp[j]` -> `dp[j] + a` (인덱스는 그대로, A 합만 증가)
- B에게 배정: `dp[j]` -> `dp[j + b]`로 이동 (B 합이 b만큼 증가, A 합은 그대로)

이 전이를 인덱스가 감소하는 방향(`j: m-1 -> 0`)으로 뒤집어서 보면 배열 하나만으로 갱신할 수 있다. j를 내림차순으로 순회하면 `dp[j]`를 갱신하는 시점에 `dp[j]`와 `dp[j-b]` 모두 아직 이번 물건이 반영되지 않은 값이라, 물건마다 정확히 한 번씩만 반영된다. 물건의 흔적 값이 항상 1 이상이라 인덱스가 반드시 더 작은 쪽으로만 참조되는 것이 이 방식이 성립하는 전제다.

모든 물건을 처리한 뒤, `dp[j] < n`을 만족하는 `j (0 <= j < m)` 중 `dp[j]`의 최솟값이 답이다. 그런 j가 없으면 -1을 반환한다.

시간복잡도는 O(len(info) * m)으로, 최대 40 * 120 = 4800회 연산이라 넉넉하게 통과한다.

## 풀이

```java
import java.util.Arrays;

public int solution(int[][] info, int n, int m) {
    int INF = 121;
    int[] dp = new int[m];
    Arrays.fill(dp, INF);
    dp[0] = 0;
    for (int[] item : info) {
        int a = item[0], b = item[1];
        for (int j = m - 1; j >= 0; j--) {
            int viaA = dp[j] + a;
            int viaB = j - b >= 0 ? dp[j - b] : INF;
            dp[j] = Math.min(viaA, viaB);
        }
    }
    int res = INF;
    for (int j = 0; j < m; j++) {
        if (dp[j] < n) res = Math.min(res, dp[j]);
    }
    return res == INF ? -1 : res;
}
```

## 회고

처음에는 물건마다 `next = dp.clone()`으로 시작해서 이전 상태를 그대로 복사한 뒤 두 전이를 얹는 방식으로 짰다. 그런데 이 방식은 물건을 아예 배정하지 않고 넘어가는 경우까지 허용해버려서 오답이 났다. 이 문제는 모든 물건이 A 또는 B 중 하나로 반드시 배정돼야 하는 문제라, "아무것도 안 하는" 선택지가 있으면 안 됐던 것이다. 이후 배열 하나만 두고 인덱스를 역순으로 순회하며 갱신하는 방식으로 정리하니, 복사로 인한 문제도 자연스럽게 해결됐다.

## 문제

> 링크: [프로그래머스 12949](https://school.programmers.co.kr/learn/courses/30/lessons/12949)

2차원 행렬 arr1(n×m)과 arr2(m×k)를 곱한 결과 행렬(n×k)을 반환한다.

## 접근

### 루프 순서를 i-k-j로 구성해 캐시 최적화

행렬 곱셈 공식 `result[i][j] = Σ arr1[i][t] * arr2[t][j]`를 그대로 구현하되, 루프 순서가 성능을 결정한다.

**i-j-k 순서의 문제:** `jdx` 고정 + `k` 변화로 arr2를 열 방향으로 읽어 캐시 미스가 발생한다.

**i-k-j 순서의 개선:** `kdx` 고정 + `j` 변화로 arr2를 행 방향으로 읽어 연속 메모리에 접근한다. 또한 `arr1[idx][kdx]`는 내부 j 루프 동안 값이 바뀌지 않으므로 `val`로 캐싱해 반복 참조를 없앤다.

## 풀이

```java
public int[][] solution(int[][] arr1, int[][] arr2) {
    int[][] result = new int[arr1.length][arr2[0].length];
    int idx = 0, kdx = 0;
    while (true) {
        int val = arr1[idx][kdx];
        for (int j = 0; j < arr2[0].length; j++) {
            result[idx][j] += val * arr2[kdx][j];
        }
        kdx++;

        if (kdx == arr2.length) {
            kdx = 0;
            idx++;
        }

        if (idx == arr1.length) break;
    }
    return result;
}
```

## 회고

루프 순서만 i-j-k → i-k-j로 바꿨을 뿐인데 실제 벤치마크에서 시간·메모리 모두 감소했다. 캐시 최적화는 이론으로만 알고 있었는데, 100×100 수준에서도 실측으로 확인되니 확실히 와닿는다.

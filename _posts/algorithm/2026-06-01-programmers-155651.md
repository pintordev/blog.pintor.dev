## 문제

> 링크: [프로그래머스 155651](https://school.programmers.co.kr/learn/courses/30/lessons/155651)

대실 예약 목록과 퇴실 후 10분의 청소 시간을 고려하여 필요한 최소 객실 수를 구하는 문제.

## 접근

### 정렬 + 우선순위 큐

예약을 시작 시각 기준으로 정렬한 뒤, 퇴실+청소 종료 시각을 기준으로 하는 minHeap으로 현재 사용 중인 방을 관리한다.

새 예약을 처리할 때, 힙에서 종료 시각이 현재 시작 시각 이하인 방을 모두 제거하면 힙에 남은 원소가 현재 시점에 동시 사용 중인 방의 집합이 된다. 여기에 현재 예약을 추가한 후 힙 크기의 최댓값을 갱신하면 필요한 최소 객실 수를 구할 수 있다.

### 타임라인 (차분 배열)

시각의 범위가 최대 1,449분(23:59 + 10분)으로 고정이라는 점을 활용한다.

크기 1,450짜리 배열을 타임라인으로 사용하여 입실 시각에 `+1`, 퇴실+청소 종료 시각에 `-1`을 기록한다. 이후 누적합을 계산하면서 최댓값을 구하면 동시에 사용 중인 방의 최대 수를 알 수 있다.

정렬이 필요 없고 힙도 사용하지 않아 O(n + T) — 사실상 O(n) — 으로 더 단순하다.

## 풀이

```java
public int solution(String[][] book_time) {
    int[] timeline = new int[1450];
    for (String[] bt : book_time) {
        timeline[parseTime(bt[0])]++;
        timeline[parseTime(bt[1]) + 10]--;
    }
    int max = 0, cur = 0;
    for (int t : timeline) {
        max = Math.max(max, cur += t);
    }
    return max;
}

public int parseTime(String bt) {
    return Integer.parseInt(bt.substring(0, 2)) * 60 + Integer.parseInt(bt.substring(3));
}
```

## 회고

처음에는 정렬 + 우선순위 큐 방식으로 접근했다. 방 재사용 가능 여부를 판단하는 조건에서 `pq.peek()[1] <= cur[0]`이어야 할 것을 `cur[1]`(현재 예약의 종료 시각)로 잘못 작성하는 실수를 했다. 두 종료 시각끼리 비교하게 되어 아직 사용 중인 방도 힙에서 제거되었고, 결과가 실제보다 작게 나왔다.

이후 시각의 범위가 고정되어 있다는 점에 착안하여 타임라인 방식으로 전환했다. 정렬과 힙 없이 차분 배열 하나로 해결되어 코드가 훨씬 단순해졌다. 입력 범위가 제한적일 때 타임라인 접근을 먼저 고려하는 것이 좋겠다.

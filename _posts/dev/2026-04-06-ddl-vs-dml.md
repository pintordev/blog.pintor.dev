## Summary

- **DDL**: 데이터베이스의 **구조(스키마)** 를 정의하는 명령어. 실행 즉시 자동 커밋되어 롤백 불가.
- **DML**: 테이블 안의 **데이터(레코드)** 를 조작하는 명령어. 트랜잭션 내에서 실행되어 롤백 가능.
- 둘의 핵심 차이는 **"무엇을 다루는가"** — 구조냐, 데이터냐.

---

## Background

SQL 명령어는 역할에 따라 분류된다. 그 중 가장 자주 마주치는 두 가지가 DDL과 DML이다.

처음 SQL을 배울 때는 `CREATE TABLE`로 테이블 만들고 `SELECT`로 조회하는 것을 별 구분 없이 쓰게 되지만, 실무에서는 이 둘의 차이가 꽤 중요하다.

- `DROP TABLE`을 실수로 실행했을 때 되돌릴 수 없다거나
- `DELETE`는 롤백이 되는데 `TRUNCATE`는 안 된다거나

이런 상황이 생기면, DDL과 DML의 차이를 제대로 이해하지 못한 것이다.

---

## DDL (Data Definition Language)

데이터베이스의 **구조(스키마)** 를 정의하고 관리하는 명령어다.

실행 즉시 **자동 커밋(Auto Commit)** 되기 때문에 `ROLLBACK`으로 되돌릴 수 없다.

### 대표 명령어

| 명령어 | 용도 |
|--------|------|
| `CREATE` | 테이블, 뷰, 인덱스 등 객체 생성 |
| `ALTER` | 기존 객체의 구조 변경 (컬럼 추가·수정·삭제 등) |
| `DROP` | 객체를 데이터와 함께 영구 삭제 |
| `TRUNCATE` | 테이블 구조는 유지하고 전체 데이터만 삭제 |

```sql
-- 테이블 생성
CREATE TABLE users (
    id   INT PRIMARY KEY,
    name VARCHAR(50) NOT NULL
);

-- 컬럼 추가
ALTER TABLE users ADD COLUMN email VARCHAR(100);

-- 테이블 전체 데이터 삭제 (구조 유지)
TRUNCATE TABLE users;

-- 테이블 삭제
DROP TABLE users;
```

## DML (Data Manipulation Language)

테이블 안의 **데이터(레코드)** 를 조회하고 변경하는 명령어다.

트랜잭션 내에서 실행되므로 `COMMIT` 전까지 `ROLLBACK`으로 되돌릴 수 있다.

### 대표 명령어

| 명령어 | 용도 |
|--------|------|
| `SELECT` | 데이터 조회 |
| `INSERT` | 새 행 삽입 |
| `UPDATE` | 기존 행 수정 |
| `DELETE` | 조건에 맞는 행 삭제 |

```sql
-- 데이터 조회
SELECT * FROM users WHERE id = 1;

-- 데이터 삽입
INSERT INTO users (id, name) VALUES (1, 'Alice');

-- 데이터 수정
UPDATE users SET name = 'Bob' WHERE id = 1;

-- 데이터 삭제
DELETE FROM users WHERE id = 1;
```

---

## Key Differences

| 구분 | DDL | DML |
|:--:|:--:|:--:|
| 대상 | 구조(스키마) | 데이터(레코드) |
| 트랜잭션 | 자동 커밋 | 수동 커밋 / 롤백 |
| 되돌리기 | 불가 | 가능 (`ROLLBACK`) |

---

## TRUNCATE vs DELETE

둘 다 데이터를 삭제하지만, 성격이 다르다.

| 구분 | TRUNCATE | DELETE |
|:--:|:--:|:--:|
| 분류 | DDL | DML |
| 대상 | 테이블 전체 | 조건 지정 가능 |
| 롤백 | 불가 | 가능 |
| 속도 | 빠름 | 상대적으로 느림 |

조건 없이 전체 데이터를 지워야 하고 롤백이 필요 없다면 `TRUNCATE`가 효율적이지만, 실수할 여지가 있다면 `DELETE`를 사용하는 것이 안전하다.

---

## Key Point

> **구조를 바꾸면 DDL, 데이터를 바꾸면 DML.**

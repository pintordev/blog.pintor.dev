## Summary

- **OSI 7계층**: 네트워크 통신을 7개 계층으로 나눈 이론적 참조 모델. 각 계층의 역할을 명확히 분리해 설명하기 위한 표준.
- **TCP/IP 4계층**: 실제 인터넷에서 사용되는 프로토콜 스택. OSI보다 계층 수가 적고 실무 구현에 초점을 맞춘다.
- 두 모델은 계층화(layering)라는 설계 철학은 같지만, OSI는 교육/설계용 참조 모델이고 TCP/IP는 실제 동작하는 표준이라는 점이 다르다.

---

## Background

1970~80년대 서로 다른 벤더의 네트워크 장비가 난립하면서, 이기종 시스템 간 통신을 표준화할 필요가 생겼다. ISO는 이를 해결하기 위해 1984년 **OSI(Open Systems Interconnection) 참조 모델**을 발표했다. 통신 과정을 7개 계층으로 분리해 각 계층이 독립적으로 발전하고 교체될 수 있도록 설계한 것이다.

한편 OSI가 표준화되기 전부터 미국 국방부(DARPA) 주도로 ARPANET에서 실제로 쓰이던 프로토콜 스택이 있었다. 이것이 **TCP/IP**다. TCP/IP는 이론보다 실용을 우선한 결과물이며, 오늘날 인터넷의 사실상 표준(de facto standard)이 되었다. 반면 OSI 7계층은 실제 구현체로 널리 채택되지는 못했지만, 네트워크 개념을 설명하고 문제를 계층별로 분석하는 참조 틀로 지금까지 널리 쓰인다.

---

## OSI 7계층 모델

| 계층 | 이름 | 역할 | 예시 |
|---|---|---|---|
| 7 | 응용 계층(Application) | 사용자와 직접 상호작용하는 서비스 제공 | HTTP, FTP, SMTP |
| 6 | 표현 계층(Presentation) | 데이터 형식 변환, 암호화, 압축 | SSL/TLS, JPEG, 문자 인코딩 |
| 5 | 세션 계층(Session) | 통신 세션의 수립·유지·종료 | 세션 관리, 동기화 |
| 4 | 전송 계층(Transport) | 종단 간(end-to-end) 신뢰성 있는 데이터 전달 | TCP, UDP |
| 3 | 네트워크 계층(Network) | 목적지까지의 경로 설정(라우팅), 논리 주소 | IP, ICMP, 라우터 |
| 2 | 데이터 링크 계층(Data Link) | 인접 노드 간 물리 주소 기반 전송, 오류 검출 | 이더넷, MAC 주소, 스위치 |
| 1 | 물리 계층(Physical) | 비트 단위의 전기적/광학적 신호 전송 | 케이블, 허브, 커넥터 |

각 계층은 하위 계층이 제공하는 서비스만 이용하고, 자신의 기능만 상위 계층에 제공한다(계층 간 캡슐화). 예를 들어 3계층은 2계층이 어떻게 비트를 전달하는지 몰라도 되고, 그저 "패킷을 전달해준다"는 인터페이스만 신뢰하면 된다.

---

## TCP/IP 4계층 모델

| 계층 | 이름 | 대응하는 OSI 계층 | 예시 |
|---|---|---|---|
| 4 | 응용 계층(Application) | 응용 + 표현 + 세션(5~7) | HTTP, FTP, DNS, SMTP |
| 3 | 전송 계층(Transport) | 전송(4) | TCP, UDP |
| 2 | 인터넷 계층(Internet) | 네트워크(3) | IP, ARP, ICMP |
| 1 | 네트워크 인터페이스 계층(Link) | 데이터 링크 + 물리(1~2) | 이더넷, Wi-Fi |

TCP/IP는 OSI의 상위 3개 계층(응용, 표현, 세션)을 하나의 **응용 계층**으로 통합하고, 하위 2개 계층(데이터 링크, 물리)을 하나의 **네트워크 인터페이스 계층**으로 묶었다. 실제 프로토콜 설계에서 세션 관리나 데이터 표현 변환이 응용 프로그램(예: HTTP, TLS) 안에서 자연스럽게 처리되는 경우가 많았기 때문에, 이를 억지로 별도 계층으로 분리할 실익이 크지 않다고 본 것이다.

## 두 모델 비교

| 구분 | OSI 7계층 | TCP/IP 4계층 |
|---|---|---|
| 목적 | 이론적 참조 모델, 개념 설명용 | 실제 동작하는 프로토콜 스택 |
| 계층 수 | 7개 | 4개 |
| 표준화 주체 | ISO | DARPA/IETF |
| 실제 채택 여부 | 참조용으로만 널리 사용, 구현체는 드묾 | 인터넷의 사실상 표준 |
| 계층 분리 방식 | 응용/표현/세션을 명확히 분리 | 세 계층을 응용 계층 하나로 통합 |
| 설계 시점 | 프로토콜 설계 전에 모델부터 정의(선 설계) | 이미 동작하던 프로토콜을 나중에 계층화(후 정리) |

실무에서는 "3계층 문제다", "7계층 문제다"처럼 OSI 계층 번호로 네트워크 장애를 표현하는 관용어가 여전히 쓰인다. 반면 실제 패킷이 어떻게 캡슐화되고 전달되는지를 설명할 때는 TCP/IP 4계층이 더 직관적이다. 두 모델을 상호 배타적으로 볼 것이 아니라, OSI는 "개념을 나누어 이해하는 언어", TCP/IP는 "실제로 동작하는 구현"으로 함께 이해하는 것이 적절하다.

---

## Key Point

> **OSI 7계층은 네트워크를 계층별로 나누어 사고하기 위한 참조 모델이고, TCP/IP 4계층은 실제 인터넷에서 동작하는 프로토콜 스택이다. TCP/IP는 OSI의 상위 3계층(응용·표현·세션)을 응용 계층 하나로, 하위 2계층(데이터 링크·물리)을 네트워크 인터페이스 계층 하나로 통합한 실용적 모델이다. 장애 분석이나 개념 설명에는 OSI 용어를, 실제 패킷 흐름을 이해할 때는 TCP/IP 모델을 사용하면 된다.**
